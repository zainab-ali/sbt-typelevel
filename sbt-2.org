*** Tasks that read string contents from files
If there is a Task[String] which reads from a file using =IO.read= , the task will not re-evaluate when the content changes.

The correct approach is to declare a private =Task[HashedVirtualFileRef]=, then read in a separate task. The fileref doesn't need to be within the target directory.

*** Caching on task failure
Tasks that fail with sys.error seem to be re-run.

The =githubWorkflowCheck= task re-runs on failure, even if the inputs are the same.

I have published a version without failure. There is a cache hit even if the check fails, provided there is no sys.error.

They shouldn't need to, as of SBT =2.1.0-M3=. Also, tasks declared with =Def.task= are uncached.

#+begin_example
Most of these `Def.uncached` calls can be removed once we upgrade to SBT `2.1.0-M3`.

All the tasks defined in the `Tasks` object are uncached as they're defined using `Def.task`, `Def.taskDyn` or `Def.inputTask`. However `:=` still goes through the caching machinery, so needs an explicit `Def.uncached` call. In SBT `2.1.0-M3`, [simple expressions short circuit the caching macro machinery](https://github.com/sbt/sbt/issues/9830).
#+end_example
